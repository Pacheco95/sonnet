# ADR-0047: Entity references across prefab instances

- **Status:** Accepted
- **Amends:** [ADR-0028](0028-nested-scene-instances.md), [ADR-0037](0037-per-field-instance-overrides.md) and [ADR-0044](0044-apply-added-children-to-prefabs.md)
- **Date:** 2026-11-24

## Context

A door script points at a handle on the same door. Placing the door twice should give each script its own handle. Today the inspector stores a picked entity as a bare UUID in `Scripts.slots[].properties`. The picker lists scene entities and omits prefab definitions. A definition UUID can still enter a property through a hand-written file or a subtree copy. The same UUID can also occur in a label or identify a model asset. Only scripting knows the property's declaration.

The editor, player and Lua share `World::instantiate`. Flecs copies the descendant components, and the instance root can inherit a component from the prefab. Today `World::differs` can finish a comparison through a registered equality hook. The reference rule must work for both inherited and copied values and keep the common comparison cheap.

Existing project scenes already use bare UUIDs to name specific scene entities. Their meaning must survive a load, save and cook. Two operations change identities here. Placing a prefab gives each source entity a counterpart in an instance. Copying an authored subtree gives its entities fresh identities in a new document. Promotion performs both operations, and an existing switch in the scene must keep controlling the handle on the particular door from which it was promoted. [Original issue](https://github.com/Pacheco95/sonnet/issues/627) · [Added-subtree Apply](0044-apply-added-children-to-prefabs.md)

## Decision

The [acceptance tests](#acceptance-tests) cover the behavior below. The [performance criteria](#performance-acceptance) cover the offered check and instantiation.

### File form and lookup

In a script slot's embedded properties object, a bare UUID string in a declared entity property names an absolute target. A relative reference is a whole property value of the form `{"$entity":"<uuid>"}`. Its UUID names the target in the containing document's identity space. JSON null clears the property and an absent property follows the declared script default. A marker is an atomic value for patch and merge, including in a property object with a `$removed` entry.

Scripting accepts both forms for an entity property. It reports a malformed marker, including extra keys, an invalid UUID or a marker on a property of another type, through the existing warning and default-value path. The inspector displays the target and a Relative / Absolute toggle. Picking a new target or dropping an entity writes a relative link. The inspector serializes these edits into the slot. Lua assignment to `self.target` changes the running script instance. `entity:set` writes reflected component data as supplied. Neither operation implicitly authors a marker. The Lua declaration reader converts class defaults separately; an absent slot property continues to use its declared default. The toggle converts a populated property in either direction as one undoable edit with the same UUID. Reselecting the current target leaves its form alone. For a target outside the instantiation map, toggling changes the stored form while both forms still resolve to the same live scene entity. This gives authors an explicit way to prepare legacy internal links before saving a selection as a prefab.

### Instantiation, comparison and Revert

After `World::instantiate` adopts the copied children, the prefab root maps to the instance root and each source descendant maps to the copy given by `instancedIdentity(instance, source)`. Translate matching markers in registered reference-bearing members, currently `Scripts.slots[].properties`. Future entity-reference members explicitly register their semantics. The editor, player, bundle loader and Lua all use this instantiation path. Absolute targets, asset values, literal strings and object keys keep their values. For a marker outside the map, retain its UUID. Lua's ordinary world lookup resolves it whenever the target is present and yields nil when absent. Apply eligibility is a separate authoring rule.

An inner instance translates its markers when the containing prefab is built. Placing the containing prefab then maps its own subtree identities, including the distinct copies from two placements of the same inner prefab. Descendants receive translated values in their owned components. An instance root takes ownership of an inherited component only when a target in it changes.

For a registered embedded member, the raw JSON text may be skipped when it contains neither the quoted key `"$entity"` nor a backslash. If either occurs, parse and inspect whole property values. This also recognizes `{"\u0024entity":"<uuid>"}` in a directly constructed C++ slot. No cache or canonical JSON writer is required for correctness.

For comparison, the followed value is the source translated into the current instance's space. Use it for `World::differs`, member patches, inspector marks, Revert and the Apply target walk, translating one level at a time. When a marker can affect the comparison, translate before using an equality shortcut. An override can equal the raw source while explicitly targeting the original prefab child. Save that override in the containing document's space and load it after instantiation. Omit an unchanged component or descendant override.

Reverting a member or property restores that portion of the followed value immediately. Whole-component Revert restores it on a descendant. A root retains an owned component if translation is needed and resumes inheritance otherwise. A reverted value contributes no patch on save.

### Copy, promotion and Apply

For Duplicate and Save as prefab, `withFreshIdentities` maps each copied identity to its counterpart under the new root. Include instance parts with no serialized entry by deriving their new identities from the new instance root and their source identities. Rewrite structural fields according to the scene schema. For an entity property whose target was copied, replace its UUID with the counterpart's UUID **and preserve its stored form**. References outside the copied subtree keep their target and form.

Before Save as prefab or promotion writes anything, collect the internal bare entity links that the operation will remap to definition entities. If any are present, the confirmation lists their count and each source entity, script slot, property and target. For a door promoted with a bare link to its handle, explain that the rebuilt door and future placements will target the handle on the prefab definition. Apply all presents the same details in its existing single confirmation for the whole command. The implementation card decides whether to group the link warnings by destination file or by individual promotion within that confirmation. The author can proceed with those absolute links or cancel and toggle selected properties to Relative before retrying. Cancellation preserves the document and command history. Duplicate stays in the scene and needs no such confirmation.

For Apply of a member, component or script property, translate each marked target back to its counterpart at the selected prefab level. Offer a level only when every marked target in the applied portion has a counterpart there. A scene target can resolve live and still make the level ineligible. For a bare entity reference, refuse a live non-prefab target, including a part of the applying instance. Other instances would otherwise point back into this particular scene. A bare target that names a prefab definition or is currently unresolved keeps its UUID and form. Null remains a valid clear. Use the same eligibility check when offering a level and when executing Apply or Apply all. Report a refusal with its entity, component and property.

Promotion of an added subtree uses two maps with different destinations. Given a local handle `H`, allocate its fresh prefab identity `P` once, then compute the placed handle's identity `C` with `World::copiedIdentity` through the selected level.

| Document being edited | Identity change | Result |
|---|---|---|
| Promoted subtree in the target prefab | H → P | The subtree's structure and internal entity links name the newly authored prefab entities. On placement, marked links follow each copy and bare links name the definition. |
| Applying scene | H → C | Remove the old local entries and repair surviving inbound links and structural references so the switch still controls the handle on the applying door. |

Preserve the form of every repaired reference in both documents. Allocate identities for the entire subtree before translating any link. Keep ADR-0044's refusal of outbound links from an added subtree, including links to other parts of the same instance. For nested instances, include parts omitted from the document in each map. Derive the new part from the new nested root in the prefab, then fold through the selected placement chain for its scene counterpart. Store the allocated identities with the undoable command so redo reproduces both destinations.

During Apply, copy or repair, the editor uses the script declaration to distinguish a bare entity target from identical text in a label or asset property. If a declaration is unavailable and an ambiguous bare value matches an identity that the operation must rewrite or validate, refuse before mutation and identify its slot and property. An ambiguous candidate is ineligible in the offered check. Show the reason for a disabled action and include it among Apply all's kept overrides. Inspect only candidates that reach eligibility. Use the Lua runtime's existing per-script class and declarations cache. First load and a changed script or required module may execute top-level Lua. Repeated queries reuse the declarations for the same revision. If a reload fails, a retained last-good class supplies the declarations while that class is active, matching the inspector. A script with no usable class has unavailable declarations. Recheck eligibility on execution. Ordinary loading, saving and cooking preserve bare values without declarations.

### Versioning

Scene and prefab version 10 and bundle version 22 advance to 11 and 23. Reader-only work may land first. The **first change that can persist a marker** includes the version bumps and the corresponding writer and reader checks. The new reader honors a well-formed marker even in a version 10 document, where an object was previously invalid for an entity property. Existing bare values retain their absolute meaning across load, save and recook. Resave repository fixtures with their respective scene and prefab serializers. The behavior change takes a MINOR engine bump before 1.0.

## Consequences

The picker changes its default from absolute to relative. If a door’s handle was picked before this change, every placement still targets the UUID stored in that bare link. Picking the handle after this change makes each placed door target its own handle. This difference applies when the target belongs to the prefab being placed. Both forms still resolve an external target by its stored UUID. Saving or promoting legacy internal links can require a confirmation. Markers that translate require a mapped comparison even when raw values are equal. Escaped JSON incurs parsing, but once parsing rules out a marker the ordinary equality shortcut is available.

The character sample places a Character whose `route` property names the scene's Route entity. This override belongs to the instance root. It continues to load and run. Today property Apply copies that UUID into the prefab. Under this decision the editor refuses that Apply while Route is live, so the value stays a scene override. ### Acceptance tests

- World and Lua tests place two instances and two nested placements. Cover root, sibling and descendant targets, an external target present and absent, and equal UUIDs in entity, text and asset properties. Exercise an escaped marker key in a directly constructed slot through instantiation and comparison. Verify malformed-marker warnings and atomic patch and merge.
- Scene round trips preserve an explicit override pointing at the original prefab child, omit an unchanged instance override and follow a later edit to another member. Revert a property, a descendant component and a root component. Verify the live target before reload and the absence of a saved patch. Round-trip an inner instance override that points to an outer sibling, then place the outer prefab twice.
- Inspector tests toggle both ways, undo and redo with the same target, reselect a target without changing form, and pick and drop new relative targets. Exercise inner and outer Apply levels and a relative target with no counterpart, a bare live instance part, a bare prefab definition and an ambiguous bare value with an unavailable declaration. Load a prefab with a legacy bare handle link and place it twice. Verify both doors resolve the definition handle. In a scene subtree, pick its handle as a new link, use Save as prefab, place the result twice, and verify each door resolves its own handle. Test the Character route override through offered and executed Apply, and check its live scene target after refusal.
- Extend the existing editor test “apply all is offered exactly when its plan lists a file”. With a bare entity property pointing to a live scene entity as the only override, assert that `applyAllOffered` is false, `applyAllPlan.files` is empty, and `kept` names the refused property and its reason. Then add an independently applicable override to the same instance. Assert that the offer becomes true, the plan lists only the applicable change for writing, and the bare property remains in `kept` for the same reason. Undo the applicable override and verify the refused-only result returns. [Apply-all consistency test](../../modules/editor/tests/ApplyToPrefabTests.cpp)
- Duplicate and Save as prefab tests copy absolute and relative links to the same internal target, including an override targeting a part omitted from the document. Place the resulting prefab twice and assert which entity each link resolves to. For Save as prefab, verify the confirmation identifies the internal bare property, cancel without writing, then retry and proceed. Check that external references and literal UUID text survive.
- Promote a handle with an internal relative link and a switch outside the subtree pointing in. Inspect the prefab target P and scene target C separately. Verify two placed doors resolve their own relative links, the switch follows the applying door, undo restores H and redo restores the same P and C. Repeat with a bare internal link. Confirm the warning in single Apply and Apply all, then verify that proceeding points the applying door and the second placement at P. Cancel and retry with a relative link in a separate case. Exercise both inbound forms and outbound refusal.
- Cook a project with adjacent absolute and relative properties containing the same prefab-child UUID. Run the player against the source and then the cooked bundle. Place two instances, one from Lua. In each run assert that both absolute values resolve to the definition child and each relative value resolves to its respective placed child. Round-trip a version 10 bare value through version 11. Verify new output advertises the new format versions and older readers reject it.

### Performance acceptance

Use the existing 300-part Apply-all fixture with scripts on 30 parts. Vary markers and JSON escapes independently. On the untouched marker-free fixture, including the escaped-text variant, the offered check must take at most **1.25 times** the pre-change time and instantiation at most **1.10 times** its pre-change time. Each limit is relative to a baseline measured in the same run: the same machine, build settings and workload, with the report's measurement protocol, on the commit before the first change of this decision and on the candidate. The report's figures, 2.5 ms Debug and 0.33 ms Release for the offered check, are the reference values, so the expected limits are 3.125 ms and 0.4125 ms on that machine; on another machine the baseline decides, never the absolute figure. [Apply-all benchmark](../reports/apply-all-offered.md)

Measure changed bare UUID properties that reach eligibility, including an eligible definition target and a refused live scene target that forces the walk to continue. Report first lookup, repeated lookups and the first lookup after script reload separately. Include an unavailable declaration, the marker variants and instantiation of the largest repository prefab in the report. These measurements characterize paths outside the untouched-fixture limits.

A repeatable limit violation blocks acceptance until a fix passes the same benchmark or a revised budget is explicitly agreed and recorded. Profile parsing, comparison and declaration lookup separately. Any faster precheck must recognize escaped keys. A proposed cache must agree with the uncached traversal after prefab edits, nested rebuilds and undo. Publish the measurements and update the world, scripting, editor and asset format documentation with implementation.

## Alternatives considered

- **Resolve in Lua or read declarations during loading.** Lua-only resolution leaves the editor and scene serializer with different targets. Reading declarations during loading would make world reconstruction depend on executable script code.
- **Convert internal bare links automatically on Save as prefab or promotion.** This helps older scenes acquire relative links but also changes deliberate absolute links. The inspector toggle lets authors choose which links follow future placements.
- **Infer references from UUID equality.** Model roots share identities with assets, and literal text can equal an entity identity.
- **Convert every repaired bare link to a marker.** A copy would change what a later placement targets, even though its author only asked to duplicate it.
- **Reuse the prefab identity map for scene repair.** A scene switch would point at the prefab definition after promotion.
- **Require literal marker spelling in raw JSON.** Direct C++ callers can supply valid escaped JSON without passing through a canonical serializer.
- **Convert the form by reselecting the same target.** A visible toggle exposes both forms and supports conversion in either direction.
- **Cache marker presence per prefab.** Editor writes and nested rebuilds require invalidation. Start with the text precheck and use benchmark evidence to justify additional state.
- **Type entity members in reflection or with a C++ type.** No reflected member holds an entity today, and a script property's kind is declared in Lua, so a type would still have to reach the loader, the diff and the bundle reader for script properties. A future reflected member registers its semantics instead.
- **Make every bare value relative, with a migration.** About forty absolute references in the sample scenes would have to be told from relative ones, which only a script declaration can do, and an absolute reference is a legitimate thing to store.
- **Allow references from an added subtree to other parts of the same instance.** It needs the counterpart at the target level, which a deeper target may not have. ADR-0044's refusal stays until a case needs it.
- **Docs only.** The meaning of a stored value, the files' versions and three accepted ADRs change.
