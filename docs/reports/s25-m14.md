# M14 phone target on a Galaxy S25 Ultra

Measurement of the 33 ms phone target, 2026-10-10, with the stress scene (`scenes/stress.scene.json` of the basic sample, built by `scripts/stress.lua`: 10 000 alternating boxes and 320-triangle icospheres and 100 point lights). No engine code changed for the measurement; the scene itself was corrected on the way ([PR 150](https://github.com/Pacheco95/sonnet/pull/150)).

## Setup

- Device: Galaxy S25 Ultra (Snapdragon 8 Elite, Adreno), Android with Vulkan 1.3, 1080×2340 portrait.
- Build: `android-release` APK from the branch of the stress scene, NDK r30, bundle cooked with `sonnet_cook --platform android` (the device reports BC, so textures are BC7).
- Run: `--scene scenes/stress.scene.json --play N`, which logs the capture frame times over the last 100 frames with per-pass GPU timestamps. FIFO presentation with a 60 fps request.
- The GPU clock cannot be pinned without root, so passes are compared by share, not by absolute time, across clock states.

## Results

GPU ms is the sum of the per-pass timestamps over the last 100 frames. Every run is Release, TAA on.

| scene | run | GPU (ms) | clock | thermal status |
|---|---|---|---|---|
| 960-triangle sphere | cold, 3 s | 22.5 | 1200 MHz | 0 |
| 960-triangle sphere | sustained, 600 frames | 36.46 | 734 MHz | 2 by 270 s |
| icosphere (current) | cold, 3 s | 19.6 | 1200 MHz | 0 |
| icosphere (current) | sustained, 600 frames, about 18.5 min | 31.85 | 734 MHz from 570 s | 3 by 870 s |

With the scene as it is now, the sustained run meets 33 ms by about 3.5 %: 31.87 ms apart, CPU 17.1 ms, skin 37.9 °C at the start and 45 °C by 870 s. The phone target is met on this device, with a thin margin and only after the clock has dropped by 39 %.

The first scene used the built-in sphere (960 triangles), which is more than four times the desktop benchmark's sphere (224) and missed the target when sustained (36.46 ms). [PR 150](https://github.com/Pacheco95/sonnet/pull/150) switched it to the built-in icosphere (320 triangles), the closest built-in mesh to the benchmark.

## Where the time goes

Sustained, icosphere scene: shadow cascade 3 is 13.96 ms (44 % of the frame) and `forward` 10.2 ms; cold, cascade 3 is 8.4 ms. Every pass scaled by about 1.6 times with the clock, so the shares hold between the cold and the throttled runs.

Cascade 3 is the far cascade. A cold test of what drives its cost:

| casters | triangles each | cascade 2 (ms) | cascade 3 (ms) | GPU total (ms) |
|---|---|---|---|---|
| spheres, 32×16 | 960 | 1.4 | 9.4 | 22.5 |
| icospheres | 320 | 1.04 | 8.4 | 19.6 |
| boxes only | 12 | 0.47 | 1.07 | 13.7 (60 Hz limited) |

The far cascade follows the caster triangle count but saturates: a third of the triangles saves a tenth of the time. Instance count alone is cheap (10 000 boxes). The mechanism was not found, and a guess would not be a finding. It is a tuning opportunity for a scene that needs more than the target, not a reason for a decision record.

## Reproduce

```sh
adb install --user 0 sonnet_player.apk
adb shell "am start -S -W --user 0 -n io.github.pacheco95.sonnet/.SonnetActivity --es args '--scene scenes/stress.scene.json --play 600'"
```

The clock is `/sys/class/kgsl/kgsl-3d0/devfreq` and the thermal state `dumpsys thermalservice`; sampling both every 30 s shows the drop. Start from a cooled phone: a warm start brings the throttle forward. See [Running on Android](../player.md#running-on-android) for the build.

The iPhone result for the same scene is in [iphone-m14.md](iphone-m14.md).
